Learning Resource Kit

One layer, ten resources

Each of the ten learning resources on this profile is a single authored page. The kit adds what a page cannot author by hand: a consistent header, saved progress, a quiz that records standard learning statements, and a print layout. This demo is the kit applied to itself.

Summary

What the kit does, in one paragraph

A resource keeps its own HTML and stylesheet. It vendors lr-kit.js, lr-kit.css and the Executive Shell, and adds a config.js with a title, tagline and five quiz questions. The kit indexes the page’s sections, mounts the shell with live KPIs (sections, reading time, sections opened, quiz score, statements), makes sections collapsible with keyboard support, and appends a quiz whose answers are recorded as xAPI 1.0.3 statements in the reader’s browser. Nothing leaves the page.

Progress

Sections opened, saved locally

When a collapsed section is opened for the first time, the kit records its id under lr:<resource>:progress in localStorage and emits an experienced statement. The KPI strip updates immediately and the count survives a reload. Storage that throws — private windows, blocked site data — degrades to memory for the session rather than breaking the page.

Opening is the signal, not scrolling: a heading passing through the viewport says nothing about reading, and the kit does not pretend otherwise.

Quiz engine

One attempt, an explanation, a statement

Questions are plain data: id, prompt, options, answer index and an explanation. validateQuiz() rejects duplicate ids, fewer than three distinct options and out-of-range answers, and every resource’s CI runs it against that resource’s config. The engine records the first choice per question, reveals the explanation, and disables the inputs. Radio buttons inside a fieldset with a legend keep it usable from the keyboard and a screen reader.

  • answered — one statement per question, with result.success and the chosen text as result.response.
  • completed — once, when the last question is answered, with a scaled score and a 60% success threshold.
xAPI

Standard statements without a server

Statements follow the xAPI 1.0.3 shape: an Agent actor with an account (a random anon- name per browser and the resource URL as home page), an ADL verb IRI, an Activity object with a name and type, an optional result, an ISO timestamp and the version string. They are kept in a capped local store and shown as JSON at the end of the quiz so a reader — or a hiring manager — can inspect exactly what would be sent to a learning record store if one were configured.

None is sent. The content-security policy on every resource sets connect-src 'none', and the kit contains no network code.

Print

A print layout that opens everything

The print stylesheet hides the shell, navigation and buttons, expands every collapsed section, appends external link targets after their text, and avoids page breaks inside a section. A resource printed to PDF reads as the complete document rather than a list of closed headings.
